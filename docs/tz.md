# Техническое задание: Emphasis

**Версия:** 1.0 (стартовая спецификация)  
**Статус:** согласованная концепция, реализацию нужно начать  
**Назначение:** личный минималистичный time tracker для задач Todoist с PWA, офлайн-режимом и синхронизацией.

## 1. Цели и принципы

Создать быстрое, стабильное, визуально качественное приложение, в котором пользователь выбирает задачу из Todoist, запускает таймер и смотрит статистику времени. Приложение должно работать на Windows, macOS, Android и iOS, включая установку на домашний экран/как PWA. Компьютер пользователя не должен постоянно работать сервером. Предпочтительно бесплатная эксплуатация в рамках облачных free-tier лимитов.

Основные принципы: минимализм и хороший UX как у Todoist (без копирования фирменного UI), локальное владение данными, offline-first/local-first, синхронизация при наличии интернета, правильные расчёты времени, безопасность секретов, понятная архитектура для полуавтономной разработки Codex.

## 2. Зафиксированный стек

- UI: React + TypeScript (strict) + Vite.
- Стили: Tailwind CSS + shadcn/ui, иконки Lucide.
- Графики: Recharts.
- Offline: service worker + PWA manifest; локальная IndexedDB (рекомендуется Dexie).
- Backend: managed Supabase PostgreSQL, Supabase Auth, RLS; Edge Functions при необходимости безопасной интеграции Todoist.
- Размещение веб-клиента: Cloudflare Pages, HTTPS и бесплатный поддомен.
- Источник задач: официальный Todoist API, чтение активных задач и проектов.
- Git/GitHub, VS Code + Codex. Первоначально npm, если нет согласованной причины менять.

Все используемые API, квоты и актуальные версии должны проверяться Codex по официальной документации на момент внедрения. Не считать бесплатный тариф безусловным и вечным.

## 3. Пользовательские сценарии

**UC1. Первый запуск:** открывается onboarding. Можно установить PWA, войти через Supabase Auth, подключить Todoist безопасным способом (стратегия после проверки текущей API/auth документации). Описание синхронизации/офлайна понятно пользователю. Никаких обязательных платных услуг.

**UC2. Выбор задачи:** список активных задач Todoist, поиск по названию, фильтр проекта, отображение состояния загрузки/ошибки и времени последнего обновления. Последний загруженный список доступен офлайн.

**UC3. Работа:** выбрать задачу → start → pause → resume → stop. В один момент на устройстве активен один таймер. Отображать текущую длительность, название задачи/проекта и явные состояния. После stop создаётся завершённая сессия. Пауза не входит в учитываемое время.

**UC4. Надёжность:** после refresh/закрытия/открытия вкладки, сна ноутбука, фонового режима телефона таймер сохраняет верную длительность по временным меткам. Браузер не гарантирует выполнение таймера в фоне: приложение пересчитывает время при возвращении. Если устройство было выключено во время включённого таймера, пользователь может проверить/исправить длительность. Не обещать отслеживание после принудительного закрытия PWA без ограничений.

**UC5. История:** список записей с датой, задачей, длительностью, возможностью исправить длительность/заметку и удалить (с подтверждением/возможностью восстановления, если реализовано). Исторические названия задач сохраняются, даже если задача удалена в Todoist.

**UC6. Аналитика:** сумма за сегодня и неделю, произвольный период (после MVP), распределение по задачам/проектам, столбчатая диаграмма активности по дням, сортировка записей. Корректная работа с часовыми поясами, переходом через полночь и DST.

**UC7. Синхронизация:** локально изменения видны мгновенно; после подключения к сети они попадают в Supabase, затем на другие устройства при открытии/активности приложения. Показать статус последней синхронизации, pending изменения и ошибку с retry. Нельзя молча терять данные или затирать конфликтующие правки.

**UC8. Экспорт:** скачать полный JSON со сессиями и метаданными, версией формата; импортировать обратно с проверкой схемы и защитой от дублирования. Предусмотреть резервное копирование независимо от Supabase.

## 4. Функциональные требования (MVP)

### 4.1. Таймер

- Один активный таймер на устройство; старт/пауза/продолжение/остановка.
- Источник истины — начальные метки времени, интервалы и накопленная длительность, а не количество срабатываний `setInterval`.
- Локальное долговременное сохранение прогресса и завершённых сессий в IndexedDB.
- Длительность хранить в миллисекундах; пользовательский UI в `ч:мм:сс`.
- Отдельно учитывается незавершённый таймер; нельзя автоматически считать его завершённым при сбое приложения.
- Изменение системного времени/часового пояса не должно приводить к отрицательной длительности; документировать ограничения wall-clock и возможную коррекцию.

### 4.2. Todoist

- Загрузка доступных активных задач и проектов с официальных поддерживаемых endpoint-ов.
- Отображение названия задачи, проекта, даты/срока при наличии; поиск, фильтр по проекту.
- Не писать тайм-логи в Todoist и не менять задачи в MVP.
- Сохранять task ID и snapshot названия/проекта в сессии; удалённые задачи не должны ломать историю.
- Кэш задач локально для офлайна и информация об устаревшем кэше.
- Обработка 401/403/429 и ошибок сети; периодическое обновление в активном приложении без агрессивного polling.

### 4.3. Сессии и статистика

- Поля записи: UUID, Supabase user ID, Todoist task ID, optional project ID, title snapshot, start/end UTC, duration_ms, optional note, created/updated timestamps, revision and soft delete marker.
- Просмотр истории, редактирование/удаление, корректные суммы без удалённых записей.
- Сегодня, неделя, по задачам, по проектам, график по дням. Дату/неделю считать относительно явно выбранной таймзоны пользователя.
- Учитывать сессии, пересекающие границу суток (распределять по дням, а не записывать всё на дату старта).

### 4.4. PWA и интерфейс

- Installable по доступным правилам платформы; корректные manifest/icons/HTTPS/service worker.
- Приложение открывается и позволяет работать с локальными данными после первой загрузки без сети.
- Адаптивные mobile/desktop макеты, тёмная и светлая тема, keyboard navigation и доступность основных действий.
- Визуальный язык: нейтральные поверхности, сдержанный красный акцент, точная типографика, небольшие радиусы, неброская анимация, аккуратные loading/error/empty/offline состояния.
- Никакого требования полного «нативного» расширения внутри десктопного Todoist: это отдельное PWA.

### 4.5. Аккаунт и синхронизация

- Облачная синхронизация требует Supabase Auth. RLS ограничивает доступ к собственным записям.
- Запись в IndexedDB первой, durable outbox и повторная отправка в облако после reconnect.
- Идемпотентные операции, UUID, обработка ошибок и конкурирующих изменений. Конфликты правок не разрешать слепой перезаписью.
- Удаление через tombstone, чтобы оно распространялось на другие устройства.
- На MVP незавершённый таймер привязан к устройству; завершённые сессии синхронизируются. Между устройствами не обещается одновременное управление одним активным таймером.
- iOS/Android не гарантируют фоновую синхронизацию при закрытом PWA: синхронизировать при открытии и восстановлении связи.
- При выходе из аккаунта не смешивать локальные данные разных пользователей.

## 5. Безопасность и персональные данные

- **Никогда** не помещать Todoist personal API token, Supabase service_role/secret keys в фронтенд, git, исходники, сборку, URL, клиентскую БД или логи.
- Перед реализацией интеграции Codex исследует официальный OAuth/API и предлагает безопасный поток через backend/Edge Function с защищённым хранением секретов и проверкой JWT. Если выбран personal token, требуется защищённая server-side модель, шифрование и управление удалением/заменой токена; не принимать вариант с токеном в публичном клиенте.
- Supabase URL и publishable/anon key можно передавать клиенту только вместе с корректной RLS.
- Для всех пользовательских таблиц включить и проверить RLS, серверную валидацию и права доступа; тестировать невозможность чтения чужих строк.
- Экспорт/удаление пользовательских данных, отсутствие секретов в экспорте, защита от XSS и проблем со сторонними API.

## 6. Нефункциональные требования

- Приоритет: корректность и сохранность данных > безопасность > надёжность синхронизации > интерфейс > дополнительные функции.
- Быстрый старт и реакция интерфейса без ожидания сети; устойчивость при частичной потере соединения.
- Простой монорепозиторий без лишней инфраструктуры и платных сервисов.
- Автоматические тесты для логики таймера, локальных записей и синхронизации, RLS/security tests, сборка в CI.
- Понятный README, `.env.example`, миграции в git и пошаговые инструкции деплоя.
- Отсутствие собственного постоянно включённого ПК/сервера.

## 7. Ограничения и нецели первой версии

- Не создавать расширение, которое встраивается в нативный Todoist.
- Не реализовывать командные роли, общий биллинг, выставление счетов, Pomodoro, телефонные системные виджеты, global hotkeys и Tauri в MVP.
- Не обещать точный background execution при закрытом мобильном PWA.
- Не полагаться на хранение в IndexedDB как на единственную копию данных: облачная синхронизация + экспорт.
- Не добавлять автоматическое изменение статуса задач Todoist при остановке таймера.

## 8. Приёмка и порядок реализации

Следовать `docs/roadmap.md`: M0 каркас → M1 автономный таймер → M2 Auth/Supabase/sync → M3 Todoist → M4 аналитика и UI → M5 deployment. Каждый milestone сопровождается работающими проверками и коротким резюме Codex. Деплой и применение production migrations — только после проверки пользователем.

## 9. Особые риски

- Бесплатные лимиты Supabase/Cloudflare, автопауза неактивного проекта и доступность услуг могут меняться. Проверить тарифы до деплоя.
- Безопасное хранение Todoist-токена требует серверного решения; не сводить интеграцию к `fetch` с токеном в браузере.
- Конфликты при синхронизации, временные зоны, DST, часы устройства и удаление данных — основные технические риски.
- На iOS установка PWA/браузерные возможности отличаются от Chrome; тестировать на реальном устройстве.

## 10. Результат

Готовый URL с installable PWA, локальным автономным таймером, безопасным получением задач Todoist, синхронизацией завершённых сессий через PostgreSQL и аккуратной статистикой. После настройки облака работающий домашний ПК не требуется.
